# オンライン MCP

AirDesk のオンラインゲートウェイを使う場合は、最初のツール呼び出しの前にこの文書を読んでください。
操作の許可、対象 OS ガイド、後片付けの手順はスキル本体に従います。[SKILL.md](../SKILL.md)

## オンラインモードの仕組み

- エンドポイントは `https://mcp.airdesk.co.kr/mcp` です。ステートレスな Streamable HTTP を使います。
- 既定の **ブリッジモード** では、ゲートウェイが呼び出しをアカウントのブリッジ PC に中継し、
  その PC が対象を操作します。
- **直接接続** (`direct_host`) では、ゲートウェイが MCP 呼び出しと結果を対象ホストとの間で中継します。
  アカウントで直接接続が有効になっていて、対象が対応する場合に利用できます。
- ツール一覧に `local_*` ツールがない、または `initialize` の案内文がオンラインゲートウェイを
  説明している場合はオンラインモードです。クライアント名からモードを推測しないでください。

## サインイン

- **OAuth**(推奨): Claude と ChatGPT のコネクター、Claude Code、Codex
  (`codex mcp login airdesk`)、VS Code、Cursor、OpenCode、Gemini CLI は AirDesk の同意ページを
  開きます。AirDesk にサインインし、アカウントで求められる場合は 2 段階認証を完了してください。
  スコープ、有効期限、許可するコンピューター、必要に応じてブリッジ PC を選び、ブラウザーで承認します。
- **API キー**: アカウントの所有者がマイページ → API キーで `amk_...` キーを作成します(2 段階認証が
  必要)。外部エージェントの MCP クライアントに上記 URL を登録し、環境変数 `AIRDESK_MCP_KEY` または
  クライアントのシークレットから `Authorization: Bearer <API key>` を送ります。既存のキーに指定された
  ブリッジ PC は、ブリッジモードの選択に使われます。
- キー、パスワード、2 段階認証コードはクライアントのシークレット管理で扱い、チャット、URL、
  ログ、共有する設定ファイルに含めないでください。サーバーが `MCP_KEY_INVALID` を返したら、
  ユーザーに再度サインインするか
  クライアントのキーを置き換えるよう依頼し、ループで再試行しないでください。

## スコープ

| スコープ | 許可される操作 |
| --- | --- |
| `observe` | 検出、状態、`hostId` での接続、スクリーンショット、スナップショット、find/get/is、一覧、wait。ブリッジモードでは `remote_performance_diagnostics` も利用できます。 |
| `input` | 権限とホストで許可された入力、アプリ名による起動、クリップボードなど。ブリッジモードでは `remote_debug_mode` と 9 桁のリモート ID での接続も対象です。 |
| `terminal` | ブリッジモードでの `terminal_*`、シェルやスクリプトホストの起動または `args` 付きの起動に必要です。 |

`tools/list` には現在の権限で利用できるツールが表示されます。更新後のオンラインカタログでは
`observe` 権限でも `remote_desktop_batch` が表示されます。ゲートウェイはバッチに含まれる
コマンドごとに必要なスコープを確認します。観察だけのバッチには `observe` が必要です。
入力やターミナルのコマンドを含むバッチには、対応するスコープも必要です。現在のゲートウェイで
バッチが表示されなければ、一覧にある個別のツールを呼び出してください。`MCP_SCOPE_REQUIRED`
は不足しているスコープを示します。必要なスコープをユーザーに伝え、再承認するか新しいキーを
作成してもらってください。低いスコープのツールで同じ効果を出さないでください。たとえば
`input` だけのときに GUI のターミナルへコマンドを入力しないでください。

## ブリッジ PC なしの直接接続

1. オンラインクライアントで `tools/list` を確認します。`remote_list_computers` と `remote_connect` の
   スキーマが `mode: "direct_host"` に対応している場合に進みます。表示されない場合は、現在の
   アカウントまたはクライアントで直接接続を利用できません。ユーザーに状況を伝えて停止します。
2. 接続を許可された、キーまたは OAuth グラントのアカウント自身が所有する PC を選びます。
   対象で AirDesk ホスティング、現行 AI 規約への同意、**AIによるリモートコンピューター操作 (MCP)**、
   **オンライン MCP**、操作可能なログイン済みデスクトップを確認します。入力には `input` スコープと
   対象の許可が必要です。
3. `remote_list_computers` に `{"mode":"direct_host"}` を渡します。`online` と `canConnect` が
   true の承認済みの対象を確認し、結果の正確な `hostId` を使います。共有/チームの対象や 9 桁の
   リモート ID は直接接続の対象外です。
4. `remote_connect` に `{"mode":"direct_host","hostId":"<discovered hostId>"}` を渡します。
   `video`、`showWindow`、`fps`、`codec`、`width`、`height` を省略します。対象のデスクトップを
   agent-desktop のスナップショットやスクリーンショットで確認できます。
5. 接続が成功したら、結果の `structuredContent` から `sessionId` と `targetOs` を取得します。`remote_status` に
   `{"sessionId":"<returned sessionId>"}` を渡し、`connected: true` と `mode: "direct_host"` を
   確認してください。引数なしの `remote_status` はブリッジの状態を調べます。直接接続の準備や
   入力可否は、対象の同意、接続結果のデスクトップ機能、対象 OS ガイドに沿った再観察で確かめます。
6. `remote_desktop_*` に同じ `sessionId` を渡し、接続時と同じキーまたは OAuth グラントを使います。
   終了時は `remote_disconnect` に `{"sessionId":"<returned sessionId>"}` を渡します。

直接接続にはコントローラーのリモートウィンドウ、映像ストリーム、ターミナルがありません。
バッチはコマンドごとにスコープとホストの許可を確認し、キーやボタンの押下保持と解放は個別に呼び出します。

直接接続の `BRIDGE_OFFLINE` は対象ホストに到達できない場合に返ることがあります。対象の起動、
サインイン、ホスティング、オンライン MCP の状態を所有者に確認してください。
`MCP_SESSION_NOT_OWNED` の場合は、使用中のグラントとセッションを確認します。セッションが終了して
いた場合は、許可された対象を改めて検出してから再接続します。直接接続の失敗を受けてモードを変更する場合は
ユーザーの了承を得てください。

### 直接接続でのアプリ起動

対象が対応している場合は、`input` スコープで `remote_desktop_launch` を単独で呼び出します。
対象が解決できるインストール済みアプリ名を指定します。macOS ではバンドル ID も指定できます。
パス、起動引数、作業ディレクトリ、環境変数は省略します。

対応ホストの所有者は **MCP 直接接続でのアプリ起動** の設定で **起動許可リスト** と **起動ブロックリスト** を管理します。
実際のプロセス名をカンマまたはセミコロンで区切って入力します。macOS ではバンドル ID も入力できます。
許可リストを `*` なしで空欄にすると、AirDesk が解決できるインストール済みアプリをすべて許可します。
ブロックリストに一致する項目があれば、常にそちらが優先されます。
対象は解決したアプリの識別子を確認し、起動ツール自体のブロック設定も適用します。

## ブリッジ PC の追加確認

最初の `remote_connect` の前に、`remote_status` で SKILL のコントローラーのブール値が true である
必要があります。ブリッジ PC の所有者は AirDesk にサインインし、現行 AI 規約へ同意し、
**AIによるリモートコンピューター操作 (MCP)** と **オンライン MCP** を有効にします。
インストール済み Windows の AirDesk 1.0.71 以降では、ユーザーがアクティブなコンソールへサインイン中、
`AirdeskService` がブリッジを動かします。サービスを停止するか Windows からサインアウトすると終了します。
macOS、Windows ポータブル版、以前の Windows 版では、AirDesk アプリを起動したままにします。

- `BRIDGE_OFFLINE`: ゲートウェイがブリッジに接続できませんでした。所有者に PC がスリープしていないことと、
  上記の動作条件を確認してもらってください。Windows サービスを使う場合はコンソールへのサインインと
  `AirdeskService` の状態を、アプリがブリッジを実行する場合は AirDesk の起動状態を確認します。
  課金されません。繰り返し確認せず、所有者が準備できたと伝えてから再試行してください。
- `BRIDGE_AMBIGUOUS`: 複数のブリッジ PC がオンラインで、権限が 1 台に固定されていません。同意画面か
  キーの作成画面で PC を指定してもらってください。
- `MCP_MODE_DISABLED` / `MCP_ONLINE_DISABLED`: MCP モードかオンライン MCP がオフ、またはアカウントで
  まだオンライン MCP を使えません。所有者に依頼し、自分でオンにしないでください。
- ブリッジ PC の所有者は、オンラインの呼び出しで使えないツールを指定できます。既定は
  `remote_desktop_launch` のため、アプリの起動は通常 `BRIDGE_REJECTED` "This tool is turned off
  on this PC for online MCP." を返します。スタートメニュー、ファイル名を指定して実行、ショートカット
  などの別の入力でそのツールをまねず、所有者に依頼してください。
- 対象ホストの承認とリモートターミナルは、ローカルモードと
  同じく対象の所有者の設定です。ゲートウェイはこれらを証明しません。

## オンラインの制限

- **ショートカットの強制実行。** オンラインで `remote_desktop_press` や
  `remote_desktop_key_down` に `force:true` を指定すると `BRIDGE_REJECTED` が返ります。
  `remote_desktop_batch` 内の呼び出しや `terminal` 権限にも同じ規則が適用されます。

- **ブリッジモードはウィンドウが必須。** `remote_connect` は `video:true` と `showWindow:true` を保つ必要があり、
  `false` だと `WINDOW_REQUIRED` が返ります。リモート
  ウィンドウはユーザーのスマートフォンではなく **ブリッジ PC** に開きます。ユーザーがブリッジ PC の
  前にいない場合は、その場にいる人がウィンドウを見て操作できることを伝え、自分の観察には
  スクリーンショットとスナップショットを使ってください。
- **禁止された引数。** 更新後のオンラインツールのスキーマでは `output_path`、`out`、`image`、
  `file_url`、`pointer_image`、`cwd`、`env`、`cdp` が省かれます。ゲートウェイはバッチ内も
  含め、すべてのスコープで引き続きこれらの引数を拒否します(`MCP_ARGUMENT_NOT_ALLOWED`)。
  結果は応答で受け取り、ファイルに書く別の方法も探さないでください。
- **デバイスの制限。** ユーザーは接続を許可する対象コンピューターと、使用するブリッジ PC を個別に
  指定できます。対象一覧が設定されている場合は、許可された対象だけを表示する `remote_list_computers`
  から正確な `hostId` を選んでください。9 桁のリモート ID や一覧にない対象は `MCP_HOST_NOT_ALLOWED`
  で拒否されます。既存のセッションやそのターミナルを使うときは、記録された対象とブリッジが設定済みの
  制限に照合されます。必要な情報がないか一致しない場合は `MCP_SESSION_NOT_OWNED` が返ります。
  権限やネットワークの範囲外にあるセッションは、状態や検出の結果に表示されません。
- **ブリッジモードでネットワーク変更後の再接続。** 各ブリッジ PC で有効なリモートセッションは 1 つです。接続元を確認
  できる場合、セッション ID は接続時のネットワークに紐づきます。Wi-Fi とモバイルデータを切り替えて
  `MCP_SESSION_NOT_OWNED` が返ったら、`remote_status`
  を確認し、承認済みの対象を改めて検出してください。デバイス制限付きの権限で別のネットワークから再接続
  する場合、以前のセッションで確認された対象が要求した正確な `hostId` と一致し、記録されたブリッジが
  今回選ばれた確認済みのブリッジと一致するときだけ、以前のセッションが自動で終了することがあります。
  デバイス制限のない権限では、同じアカウントの別ネットワークのセッションも終了することがあります。
  所有者が不明な場合や別のクライアントが利用中の場合は、所有者の対応を待ってから再接続してください。
  新しい `sessionId` を使い、ターミナル ID と要素の参照を改めて確認してください。

## 時間、サイズ、コスト

- 1 回の呼び出しに使えるのは約 55 秒です。`BRIDGE_TIMEOUT`、`REGION_UNAVAILABLE`、
  `OUTCOME_UNKNOWN` では、変更済みかどうかを観察してから再試行を判断してください。
- 約 5 MiB までの結果は応答にそのまま含まれます。スクリーンショットより `remote_desktop_snapshot` と
  `find` を先に使い、スクリーンショットは必要な大きさだけを求めてください。
- `remote_list_computers`、`remote_status`、`remote_disconnect`、`tools/list` 以外の呼び出しは
  課金されます。バッチはコマンドごとに数えます。Free は月 500 回、Pro は 5,000 回、Teams は
  1 席あたり 5,000 回が含まれます。
- `RATE_LIMITED`、`QUOTA_EXHAUSTED`、`MCP_BUSY` には再試行までの時間が含まれます。少なくとも
  その時間待ち、再試行は数回までにしてください。月間の上限や `MCP_SPEND_CAP` で作業が止まったら
  ユーザーに伝えてください。
- `MCP_RESULT_DELIVERED` は、同じリクエストの結果がすでに一度返されたことを意味します。現在の状態を
  改めて観察してください。

## エラーコード

| コード | 意味 | 対応 |
| --- | --- | --- |
| `MCP_KEY_INVALID` (401) | サインインがない、期限切れ、取り消し済み | 再度サインインを依頼 |
| `MCP_SCOPE_REQUIRED` (403) | 権限に `scope` がない | 示されたスコープを依頼 |
| `MCP_ONLINE_DISABLED` (403) | アカウントでオンライン MCP を使えない | 停止して説明 |
| `BRIDGE_OFFLINE` | 選択モードで対象またはブリッジに到達できない | 選択モードの事前確認を参照 |
| `BRIDGE_AMBIGUOUS` | ブリッジ PC が複数あり未指定 | ブリッジ PC の確認を参照 |
| `WINDOW_REQUIRED` | ブリッジ接続のウィンドウが無効 | ブリッジモードでウィンドウ付きで再接続 |
| `MCP_ARGUMENT_NOT_ALLOWED` | 禁止された引数 | 引数を外し、応答で受け取る |
| `MCP_HOST_NOT_ALLOWED` | 権限外のコンピューター | ユーザーに確認 |
| `MCP_SESSION_NOT_OWNED` | セッション終了、ブリッジ接続元の変更、または権限による制限 | グラントと対象を確認し、必要に応じて同じモードで再接続 |
| `already_connected` | 選択したブリッジがすでにセッションを使用中 | 自分で開いたセッション以外は所有者に対応を依頼 |
| `BRIDGE_REJECTED` / `TOOL_DISABLED` | ゲートウェイまたはホストが操作を拒否 | メッセージを伝え、対象の制限を確認 |
| `BRIDGE_TIMEOUT` / `REGION_UNAVAILABLE` | 時間内に応答がない | 再試行の前に観察 |
| `RATE_LIMITED` / `QUOTA_EXHAUSTED` / `MCP_BUSY` / `MCP_SPEND_CAP` | 上限 | 上記のとおり待つか停止 |
