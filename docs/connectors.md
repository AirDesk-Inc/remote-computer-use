# Claude Connector, ChatGPT App and Plugins

How AirDesk online MCP reaches each assistant, what this repository ships for it,
and what the gateway (`forpro-remote`, `workers/api/src/aws/mcp-*`) still needs.
Checked against the gateway source and the live endpoints on 2026-11-10. Nothing here claims a deployment or a directory listing.

## What Ships Here

| Artifact | Command | Use |
| --- | --- | --- |
| Localized skill (en, ko, ja) | `install --lang <lang>` | Local or online coding agents |
| Online MCP registration | `install --mode online [--auth key]` | Codex, Claude Code, Cursor, VS Code, Gemini CLI, OpenCode |
| Skill zip | `pack --lang <lang>` | Upload to Claude (web/desktop, then mobile) or ChatGPT skills |
| Plugin zip | `pack --lang <lang> --format plugin` | Plugin directories that accept `.claude-plugin/plugin.json` archives |
| Claude Code marketplace | `/plugin marketplace add AirDesk-Inc/remote-coumputer-use` | `remote-computer-use`, `-ko`, `-ja`; each declares the online server |

The marketplace and plugin folders are generated by `npm run build:plugins` and
checked in CI (`npm run check:plugins`). Plugins never contain a key: they
declare `{ "type": "http", "url": "https://mcp.airdesk.co.kr/mcp" }` and rely
on OAuth. `claude plugin validate` passes for the marketplace and all three
plugins.

## Claude (Connector)

- **Custom connector** (any plan that allows them): Settings → Connectors → Add
  custom connector → `https://mcp.airdesk.co.kr/mcp`. The connector syncs to the
  mobile apps. Claude discovers OAuth through the 401 `WWW-Authenticate`
  `resource_metadata`, registers dynamically (`/oauth/register`; its redirect is
  an `https` URL on claude.ai, which the gateway accepts) and uses PKCE S256.
  Sign in to AirDesk, select the scopes, expiry, allowed computers and optional
  bridge PC, then approve in the browser.
- **Skill:** upload `pack --lang <lang>` output. The connector alone already
  receives the gateway's `initialize` instructions; the skill adds the full
  gate, target-OS guide and error handling.
- **Directory listing** requires review by Anthropic. Prepare: tool
  annotations (below), a privacy policy and terms URL, support contact, logo,
  test account and a reviewer guide covering the bridge PC requirement.

## ChatGPT (App)

- **Developer mode:** Settings → Apps & Connectors → Advanced → Developer mode,
  then add a custom MCP server with the URL and OAuth. Write tools need
  confirmation per call in ChatGPT.
- OAuth fit with the gateway as implemented:
  - PKCE S256 and `code_challenge_methods_supported`: yes.
  - Dynamic client registration: yes. ChatGPT also prefers client ID metadata
    documents (CIMD), which the gateway does not support yet; DCR is enough.
  - Redirect `https://chatgpt.com/connector_platform_oauth_redirect`: accepted,
    because the metadata sets `authorization_response_iss_parameter_supported`.
  - `resource` parameter: required to be the MCP endpoint; ChatGPT sends it.
- **App submission** (platform.openai.com → Apps/Plugins) needs a public
  Streamable HTTP endpoint, identity verification, tool annotations and the
  domain challenge at `https://mcp.airdesk.co.kr/.well-known/openai-apps-challenge`.
  Skills can be submitted as the plugin zip (`.claude-plugin/plugin.json` plus
  `skills/`); OpenAI drops `userConfig`, hooks and local servers, none of which
  these plugins use.
- Mobile availability of custom MCP apps follows OpenAI's plan rules; verify on
  the target plan before promising it.

## Gateway Work

Implemented in the gateway source (`forpro-remote`):

- `tools/list` returns `title` and MCP `annotations` (`readOnlyHint`,
  `destructiveHint`, `idempotentHint`, `openWorldHint`) for every tool,
  generated with the scope classification in `mcp-tool-catalog.json`.
- The edge answers `/.well-known/openai-apps-challenge` with the token from
  `ops/aws/mcp-openai-apps-challenge.txt` (empty until the OpenAI portal issues
  one; the path is `404` meanwhile).
- The built-in `rcu` skill (`ai-rcu-skill.ts`) now takes its tools from the
  online catalog and follows this skill's workflow (target-OS guides,
  snapshot refs, dispositions) instead of the removed legacy tools.
- `initialize` instructions mention online MCP, the target-OS guide step and
  this skill.

## Security Notes for Reviewers

- The client never executes anything; the bridge PC does, under its own MCP
  mode, online MCP switch, per-PC tool deny list (default `remote_desktop_launch`)
  and denied-argument filter.
- The bridge PC needs an AirDesk sign-in and current AI terms. On Windows with
  AirDesk 1.0.71 or later installed, `AirdeskService` runs the bridge in the
  signed-in console session after the AirDesk window closes. The app runs the
  bridge on macOS, portable Windows and older Windows versions.
- Grants are per scope, optionally limited to listed computers and one bridge
  PC, expire, and are revocable in My Page. Use from a new country is recorded and,
  when mail is configured, emailed to the account owner.
- `remote_connect` online always opens the visible remote window on the bridge
  PC (`WINDOW_REQUIRED`), so a person at that PC can see and stop the work.
